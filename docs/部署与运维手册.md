# 部署与运维手册

本手册用于在 Windows 本机部署、验证和维护数仓。下列命令均在仓库根目录运行。准备 Docker Desktop、Compose v2 和 Python 3.11 或更新版本。首次拉取镜像和构建 Superset 需要网络连接。

## 准备输入

从[阿里云天池数据集](https://tianchi.aliyun.com/dataset/42)获取历史样本。按照 `source_manifest.json` 的路径放置 `天猫电商用户行为与复购数据/data_format1/data_format1/` 中的三份 CSV。输入文件由摄取程序校验大小和 SHA-256。

| 文件 | 用途 |
|---|---|
| `user_log_format1.csv` | 用户行为 |
| `user_info_format1.csv` | 用户画像 |
| `train_format1.csv` | 样本复购标签 |

`scripts/init_env.ps1` 在首次运行时生成本机 `.env`，已有配置会保留。原始 CSV 与凭据由使用者在本机准备。

## 从样本到完整看板

先启动 ClickHouse，再跑两个完整月日的行为样本，检查数据能否装载及重算。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\init_env.ps1
docker compose up -d --wait clickhouse
python -X utf8 warehouse.py --scope sample --output outputs/sample.json
python -X utf8 scripts/check_sample.py
```

样本行为应为 40,748 条，源文件重算的前五位商家结果与快照一致。随后创建并校验全量快照，发布应用视图，再启动 Superset 和 Airflow。

```powershell
python -X utf8 warehouse.py --scope full --output outputs/full.json
python -X utf8 scripts/publish_bi.py
docker compose -f compose.yaml -f compose.bi.yaml -f compose.airflow.yaml up -d --wait --build
docker compose -f compose.yaml -f compose.bi.yaml -f compose.airflow.yaml ps
python -X utf8 scripts/validate_bi.py
python -X utf8 scripts/validate_full.py
```

全量验证应得到 54,925,330 条行为原始记录、54,925,284 条有效明细和 46 条隔离记录。看板验证应返回三个看板和六张图，商家 `3828` 的 `0511` 日活为 184。

| 服务 | 连接方式 |
|---|---|
| ClickHouse | `127.0.0.1:18123`。`warehouse` 密码取 `CLICKHOUSE_PASSWORD`，`bi_reader` 密码取 `CLICKHOUSE_BI_PASSWORD` |
| Superset | [http://127.0.0.1:18088](http://127.0.0.1:18088)。本机管理账号 `admin`，密码取 `SUPERSET_ADMIN_PASSWORD` |
| Airflow | [http://127.0.0.1:18080](http://127.0.0.1:18080)。独立运行模式的登录凭据保存在容器内 `/opt/airflow/simple_auth_manager_passwords.json.generated`，由维护者在本机查看 |
| PostgreSQL | Compose 内网服务 `postgres` 保存 Superset 配置，宿主机无需直接连接 |

## 查询、重跑与发布

在本机 PowerShell 执行下方命令可查看 Airflow 登录凭据。

```powershell
docker compose -f compose.yaml -f compose.bi.yaml -f compose.airflow.yaml exec airflow cat /opt/airflow/simple_auth_manager_passwords.json.generated
```

DAG 首次部署后可能处于暂停状态。开启网页中的 DAG 开关，或在 PowerShell 执行以下命令。

```powershell
docker compose -f compose.yaml -f compose.bi.yaml -f compose.airflow.yaml exec airflow airflow dags unpause tmall_warehouse
```

- 对照运营结果时，运行 `python -X utf8 scripts/drilldown.py --merchant 3828 --mmdd 0511`，核对应用层与行为明细的 272 条行为、184 位活跃用户与 70 位购买用户。
- Airflow 中打开 `tmall_warehouse`，按需触发 `load_validate_publish`。一般验证选择 `scope=sample`、`purpose=normal` 和 `fail_after_ods=false`。同一已发布批次重新校验后会记录 `reused: true`。
- 检查失败与恢复时，先在样本运行设置 `purpose=recovery`、`fail_after_ods=true`，读日志和失败状态。再用相同范围和用途将 `fail_after_ods` 设为 `false` 触发恢复。该批次如果已有合格快照，可复用已发布结果。故障注入只接受样本。
- 查询 `tmall_control.runs` 确认全量快照为 `published` 后，再执行 `scripts/publish_bi.py` 更新应用层指向并复核看板。Airflow 批次登记和看板发布是两个动作。视图逐个切换，若发布中断，在相同已验证快照上重跑发布脚本并检查六个视图。
- 运行摄取时选用 Airflow 或本机 Python 其中一个入口，避免两边同时装载。改动统计口径或加工 SQL 后更新 `warehouse.py` 的加工版本，再重新运行与核验。

## 常见问题

| 现象 | 检查方法 |
|---|---|
| 文件大小、摘要或表头不匹配 | 对照 `source_manifest.json` 中的路径和文件大小，重新取得原始 CSV |
| 全量写入期间 ClickHouse 连接超时 | 先用 `docker compose ps clickhouse` 确认容器健康，再重跑同一条全量命令。未通过校验的尝试不会登记为已发布结果 |
| `bi_reader` 读取原始层被拒绝 | 应用层凭据的权限范围为 `tmall_ads`。原始层检查由维护者使用仓库账号执行 |
| Superset 启动后看板无数据 | 检查 ClickHouse 容器健康状态、全量快照发布状态与 `tmall_ads` 六个视图，再运行 `scripts/validate_bi.py` |
| Airflow 批次失败 | 在 DAG Run 的任务日志定位文件、SQL 或故障注入信息，核对运行参数与控制表。修正原因后重新触发 |
| 重启后需要恢复配置 | 使用同一 Compose 项目和原有数据卷启动，保留对应的本机 `.env`，再核验应用查询 |

看板的统计口径和操作见[看板操作手册](看板操作手册.md)及[数据源与指标字典](数据源与指标字典.md)。

## 暂停本机服务

使用 `stop` 暂停组件，ClickHouse 数据和 Superset 配置仍保存在数据卷。下次在同一仓库根目录用原来的 `.env` 启动。

```powershell
docker compose -f compose.yaml -f compose.bi.yaml -f compose.airflow.yaml stop
docker compose -f compose.yaml -f compose.bi.yaml -f compose.airflow.yaml up -d --wait
```
